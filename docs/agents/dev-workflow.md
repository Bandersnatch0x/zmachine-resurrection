# 开发工作流

任务级流水线:一个想法从提出到验收的固定路径。本文档只管**单条工作流内**的阶段顺序、横切机制与粘性规则;仓库级权威与门禁命令见根 `AGENTS.md`(开工前指针、门禁段)。

## 流水线(七阶段)

正文一律用阶段名;各阶段的实际命令见文末「依赖与命令绑定」,不写入本表。

| # | 阶段 | 职责 | 出口判据 |
| --- | --- | --- | --- |
| 1 | 路由 | 判断当前情况该进哪个阶段 | 当前阶段完成且其出口判据成立,并指出下一阶段 |
| 2 | 探路 | 超会话体量的工作 → 解票地图(地图 + 子票 + 阻塞边) | 地图子票全部解决 |
| 3 | 拷问 | 核对目标与约束;授权内取舍记理由,硬门交用户,决策与术语沉淀入落点 | 无未决硬门,授权内取舍、用户裁决与术语均已入落点 |
| 4 | 成谱 | 会话共识 → 谱(规格文档) | 谱已落约定位置,可被票引用 |
| 5 | 成票 | 谱 → 可执行票 + 阻塞边 | 票全部建立且阻塞边已声明 |
| 6 | 落码 | 按票实现 | 门禁全绿 |
| 7 | 验收 | 全量测试通过后的双轴评审(标准轴 / 规格轴)+ 实现对谱的符合度核查 | 两轴发现全部裁决、符合度核查无相悖项,结论已登记 |

## 进入规则

- 只读调查:路由后调查并按其交付粒度验收,不为一次说明伪造实现票。小任务方向未定从拷问进入,方向已定从成谱进入;仅超出单会话体量的工作走探路。
- 缺陷修复:对着 bug 票直接从落码进入。
- 验收对每次交付生效、不可跳过,验收范围按交付粒度定;结论登记于 票的 Log。
- 地图式解票语义(地图 / 子票 / 前沿 / 认领 / 回写)仅在地图式解票启用时生效,存储与操作见同目录 `issue-tracker.md`。

## 自主执行契约

- 路由先登记任务的目标、仓库、写入范围、允许动作、硬门和终止条件；已有明确授权直接沿用，不索要重复授权。缺影响外部动作的范围则只继续安全的只读工作。
- 默认自主适用于授权内的实现与可逆工程选择；事实疑问由代理查证。完整自主授权覆盖的产品取舍采用可逆默认，说明理由和替代方向；未覆盖的产品方向与根规则的人工硬门仍交用户。
- 先确认实际宿主、身份、必要权限及控制入口可用，再选择执行方式。文档存在、命令名称相似、帮助可打印，都不等于自动化可用。未就绪则登记缺项；可手工完成的继续做，不伪造派发、唤醒、验证或合并。
- 写入前再核授权和暂停状态；新目标、仓库、任务集或动作不能从旧授权推导。分诊、看守与合并分别授权，后台任务启动时固定边界，撤销后停止新动作。
- 重启恢复以任务、分支、提交、外部回执和当前权限为准。保存的会话或批准结论仅为证据，不自动延长授权；旧 head 的验收不能批准新 head。
- 本仓常规阶段不因自主执行省略：既有规格继续约束落码，验收仍不可跳过。详细任务步骤、自动化契约和失败出口见同目录 `execution.md`。

## 全量测试纪律

- 落码 → 验收的门槛是**全量**套件:日志完整落盘到 `.agent/tmp/` 后整体读取;管道截断判读不算数。
- 失败先归因再处置:负载 flake → 空载复证;自伤 → 清理后复证;既有红 → 向历史溯源,定修复或重锚。
- flake 以空载复证记录后即收尾;禁止为求全绿无限重跑全量。

## 横切机制(按触发条件生效,不占流水线位置)

| 机制 | 触发条件 | 产出 |
| --- | --- | --- |
| 检验追问 | 给出用户将据以行动的方案、建议、草案、估算时 | 附 2-3 个针对本次输出的检验追问(查事实 / 问推理 / 补上下文) |
| 决策点辩论 | 有两个以上存活选项且取舍影响方案时 | 多视角反驳 → 推荐与异议;授权内可逆选择自行取舍入账,人工硬门才入待裁批次 |

## 粘性规则(整条流水线生效,跨阶段不失效)

1. 点名即常驻:用户点名过的分析手段在后续每个阶段继续使用,无需再次点名。
2. 裁决批次:每批待裁项编号成单并标注推荐项,让用户可用一句「全部按推荐」定案。
3. 自研措辞:吸收外部内容一律第一方改写;上游名词不落入产品内容与代理指令,署名面豁免。

## 通用纪律(每次交付通用)

- push 前先 fetch:核对远端分叉与祖先夹带;推送范围有分歧时列选项交用户裁。
- 被票据引用的提交不 rebase;分叉一律 merge 保 SHA。
- 声称「已覆盖 / 缺失」之前,先核实仓库现状。
- 审计与测试产物沉淀为可复跑资产,不做一次性抛弃件。
- 模糊故障报告先做端到端证据审计,拆成带优先级的具体清单再修。
- 政策切换时,在途票按开票时政策就地做完,不迁移。
- 研究与规格产物默认不进 main;晋升须显式理由,落点:`research/<主题>` 分支(不并入 main)。

## 依赖与命令绑定

- 探路、拷问、成谱、成票、落码、验收六段的执行载体**随本仓分发**:七份阶段技能在装配时整目录复制进目标项目的 `.agents/skills/<name>/`。阶段名与技能名对照:探路 → `chart`、拷问 → `drill`、成谱 → `charter`、成票 → `slice`、落码 → `build`、验收 → `gate`;验收之后的收尾为 `ship`。
- 路由与两机制(检验追问 / 决策点辩论)仍由使用者环境提供,不随本仓分发;某行未绑定时,按流水线表「职责」列手工执行等价步骤,流水线顺序不变。
- 票据后端命令明细只住同目录 `issue-tracker.md`,不进本表与 `AGENTS.md`。

| 阶段 / 机制 | 绑定命令 |
| --- | --- |
| 路由 | 手动 |
| 探路 | `chart` |
| 拷问 | `drill` |
| 成谱 | `charter` |
| 成票 | `slice` |
| 落码 | `build` |
| 验收 | `gate` |
| 检验追问 | 手动 |
| 决策点辩论 | 手动 |

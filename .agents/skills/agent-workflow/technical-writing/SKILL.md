# Technical Writing

## When to use

- A document will guide implementation, operation, review, or handoff.
- A decision or verification result must remain understandable outside the current conversation.
- A draft mixes tutorial, procedure, rationale, and reference material.

## How to use

1. Identify the reader, task, document mode, authority, and required next action.
2. Lead with the outcome and prerequisites. Use short declarative sentences and concrete terms.
3. Separate instructions, explanations, reference data, evidence, and unresolved questions.
4. Cite the source file, command, ticket, commit, or run that supports each consequential claim.
5. Review for ambiguity, stale links, duplicated truth, hidden assumptions, and missing failure paths.

## Boundaries

- Do not use prose to hide an unresolved product decision.
- Do not duplicate an authoritative specification when a pointer is sufficient.
- Do not report a check as passed when it was skipped or not run.
